## 为什么工作和聊天不能分家

企业协作里，需求通常从一句消息开始，却很快散落到任务系统、文档、代码仓库和多个 Agent Session。上下文在工具之间丢失，最终没人能准确回答“为什么这么做、谁在做、结果在哪里”。

Work & Chat 让频道、线程、任务、@、文件、评审、决策和 Agent 活动共享一段有边界的协作语境。它会参考 [Raft](https://raft.build/zh-cn/) 这类把人和 Agent 放进同一团队空间的产品机制，但保留 Pi-67 自己的任务、权限、Session 与记忆边界。

## 四层真相不能混在一起

- 对话保存沟通语境与决策背景。
- 任务记录负责人、状态、依赖和下一步。
- 产物承载真正可交付的文档、代码、数据或文件。
- Pi JSONL Session 保留 Agent 的技术运行真源。

频道和线程负责组织协作，不会取代任务、文件、代码仓库或 Session。Agent 的结果回到对话，也必须清楚标记来源、状态和待人工决定的事项。

## 下一步

先做对话转任务、Agent 进度回流、产物引用与人工决策节点，再扩展多人频道、成员身份、通知和跨团队交接；不在协作模型稳定前堆叠一个看起来热闹的聊天 UI。
