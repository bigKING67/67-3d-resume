## 治理不是管理后台附录

当 Agent 可以调用工具、读取上下文、委派团队和沉淀经验时，企业需要把身份、权限、来源、版本、运行、审计和撤销放进同一条控制链。否则“能干活”会迅速变成“出了问题说不清”。

治理首先回答六个问题：谁发起、做什么、用哪版能力、读写什么、为什么允许、怎样恢复。每个破坏性或外部可见动作都要在实际执行前经过对应边界，而不是只在最终日志里补一条记录。

## 发行也是治理

`pi-67` 负责把能力变成可安装、可升级、可诊断、可回滚的发行单元。来源、版本和健康状态决定一个 Agent 能否被组织信任；升级与回滚是独立动作，也不会因为本地构建通过就自动变成发布或生产部署。

`Agent Ops` 不单列成第七个系统，而是 Governance 的运行面：健康状态、使用量与成本、失败诊断、评测、版本升级和回滚都服务于同一套身份与组织边界。

## 下一步

把现有底座收敛为统一控制面：组织身份与 RBAC、能力目录与版本策略、隐私隔离、审计证据、停用撤销和企业级保留策略。任何控制面完成声明都需要真实身份链路与目标环境证据。
